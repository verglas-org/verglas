# Worklog

- #171: Added the prebuilt Stream Worker and Durable Object. The Worker routes authenticated JSON POST requests to the named object, while the object stores ordered records in SQL, deduplicates optional producer identities, and exposes independent bounded reads.
- #171: Fixed the internal protocol for parent runtime wiring: append uses `POST https://verglas.internal/stream/append` with a JSON-array body; read uses `GET https://verglas.internal/stream/read?after=<u64>&limit=<u32>`, with `limit` capped at 1000. The optional `x-verglas-producer-event-id` header is one identity for a single record or a JSON string array matching the request records.
- #171: Added an immutable `STREAM_SCHEMA` creation configuration with Cloudflare field types, strict unknown-key checks, hard schema/record/list ceilings, and deterministic validation outcomes stored beside every original append. Processing reads omit invalid positions with documented deserialization families while sequence continuity advances; unstructured acknowledgements remain unchanged.
- #171: Added durable input-byte, input-record, decode-error, and documented deserialization user-error counters plus a metrics endpoint. Ordering, backpressure, and lag counters are exposed under a labeled Verglas extension object; pre-implementation tests witnessed missing mixed-batch acknowledgement fields and a missing metrics route before implementation.
- #171: Corrected structured ingestion to confirm and retain invalid records with their original JSON, sequence, and validation family. Processing reads now omit those positions, return `skipped` plus an advancing `next_after`, and increment user-error metrics; the corrected tests first failed against the old pre-append-drop behavior.
- #171: Locked the source-position contract in tests: a mixed five-record append persists sequences 1 through 5 and all original JSON, while processing returns only valid sequences 1 and 5 and advances the cursor across skipped positions. Restart assertions retain the invalid position and its metric.
- #176: Added explicit Stream retention consumers with monotonic acknowledgments, minimum-watermark payload collection, and explicit detach. Collection is bounded to 1000 positions per event and continues by alarm. Producer identity tombstones survive collection, so late retries remain deduplicated while stale reads fail with the collected watermark. Staging rejected SQLite incremental autovacuum, so physical database-page and immutable CAS-object reclamation remains explicitly delegated to lineage compaction.
- #0: Corrected the immutable-schema restart test to assert the initialization failure where `blockConcurrencyWhile` now exposes it. The product continues to fail before serving when persisted and configured schemas differ.
- #0: Consume the published JavaScript Worker SDK for component and runtime-surface tests. Stream no longer reaches into an SDK source tree owned by another repository.

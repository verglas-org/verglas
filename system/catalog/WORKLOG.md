# Catalog worklog

- #172: Added the prebuilt Catalog Worker and Durable Object with immutable Turso configuration, a bounded Sink commit protocol, canonical payload digests, and replay-safe delivery receipts. REST traffic and commit delivery use one explicitly injected authority binding; the component contains no Iceberg metadata, object-store, or provider-credential implementation. Tests were written first; the initial run failed as expected because `worker.js` did not yet exist, then passed after implementation.
- #172: Deleted recursive Catalog authority configuration and REST forwarding. The Catalog object now owns namespace/table registry state in Turso across restart and invokes only the declared `ICEBERG_COMMIT → verglas-runtime` fetch capability for a new Sink commit; witnessed-red tests failed on the retired authority configuration before the implementation and all focused behavior/static tests are green.
- #interop: Added an isolated PyIceberg 0.11.1 black-box harness that drives real HTTP through the Worker/DO adapter for config discovery, multipart namespaces, table create/load/list, standard errors, and the advertised table-commit endpoint. The fixture supplies only a deterministic metadata authority and records the current commit incompatibility as a failing compatibility test instead of masking it.
- #171: Made Turso/SQLite the visible Iceberg Catalog authority. The DO now serves standard multipart namespaces, complete table create/load/list/commit/register/rename/drop responses, standard errors, UUIDv7 idempotency replay, and atomic event-scoped Sink pointer receipts; PyIceberg independently exercises config, namespace, table, and commit behavior while runtime remains only an immutable metadata publication capability.
- #171: Preserved runtime 400/409 failures as standard Iceberg REST errors and forwarded table commits as exact raw JSON strings so 64-bit Iceberg identifiers cannot be rounded by JavaScript. SQLite remains the only pointer and idempotency authority; runtime responses are bounded immutable proposals.

# Verglas ⇄ Ceph s3-tests — curated skip list (the compatibility contract).
#
# THIS FILE IS THE DOCUMENTED S3-COMPATIBILITY SURFACE OF VERGLAS.
# Every entry is a test that does NOT pass against the current server, grouped
# under a stated reason. Two kinds of reason:
#
#   • UNSUPPORTED / BY DESIGN / DEVIATION / OUT OF SCOPE / BACKEND SEMANTICS —
#     Verglas does not implement (or deliberately delegates) the feature. These
#     define what "S3-compatible" means for Verglas today.
#   • BLOCKED BY #NNN — a real Verglas bug on the *supported* surface, filed as
#     an issue. When the fix lands, delete the entry (the test must then pass).
#
# CHANGES TO THIS FILE REQUIRE REVIEW. Adding an entry narrows Verglas's stated
# compatibility; do it only with a reason a future contributor can act on. The
# harness deselects EXACTLY these nodeids (no prefix matching) and, in the
# nightly run (VG_SKIP_LIST_STRICT), warns if any entry no longer matches a
# collected test — so the list cannot silently rot.
#
# Whole unsupported feature GROUPS (versioning, tagging, lifecycle, encryption,
# object-lock, policy, website, sse, iam/sts, s3select, s3control, sns, ...) are
# excluded by pytest MARKER in run.sh, not listed here; this file carries the
# per-test residue that markers don't cover.
#
# Format: one pytest nodeid per line; "# ..." starts a comment.

# --- #208: Per-part and composite checksum FORWARDING is implemented and runs
# (the `checksum` marker group is no longer excluded, and run.sh uses boto3's
# modern checksum default). Verglas threads the checksum algorithm/type through
# create, forwards each part's checksum on upload, carries per-part checksums
# into the completion manifest, restates the FULL_OBJECT type on completion, and
# echoes the origin's composite — never recomputing. The rest of the checksum
# group passes. The ten tests below assert AWS-SPECIFIC ORIGIN BEHAVIOUR that
# current MinIO does not reproduce, so they cannot pass on a MinIO backend
# without Verglas fabricating a response the origin never returned (which the
# "never wrong / forward faithfully" invariant forbids). Each was verified by
# probing MinIO directly:
#
#   1. Bad-checksum error code. AWS returns `BadDigest` (400) when a supplied
#      checksum does not match; MinIO returns `InvalidArgument` (400). Verglas
#      forwards MinIO's code. (Same class as test_multipart_copy_invalid_range.)
s3tests/functional/test_s3.py::test_object_checksum_sha256
s3tests/functional/test_s3.py::test_object_checksum_crc64nvme
s3tests/functional/test_s3.py::test_multipart_checksum_sha256
#   2. Composite checksum in GetObjectAttributes. AWS reports the COMPOSITE
#      checksum WITH its `-<partcount>` suffix in the GetObjectAttributes
#      `Checksum` block; MinIO drops the suffix there (but keeps it on
#      complete/head). Verglas forwards MinIO's suffix-less value verbatim.
s3tests/functional/test_s3.py::test_multipart_use_cksum_helper_sha256
s3tests/functional/test_s3.py::test_multipart_use_cksum_helper_sha1
s3tests/functional/test_s3.py::test_get_multipart_checksum_object_attributes
#   3. ChecksumType on a partNumber GET. AWS returns `x-amz-checksum-type` on a
#      `GET ?partNumber=` of a checksummed object; MinIO omits the header
#      entirely (even with checksum-mode ENABLED). Verglas cannot report a type
#      the origin did not send. These three cover the FULL_OBJECT CRC helpers,
#      which otherwise complete correctly (create/upload/complete all pass).

---
title: "Cron schedules"
description: "Run daily ingestion and backfill one year with the same worker code."
icon: "clock"
---

A cron trigger gives each run a logical date and a half-open interval. The
worker reads `intervalStart` and `intervalEnd` from the CloudEvent, so a live
run and a backfill use the same code path.

The example manifest declares:

```toml
[[triggers]]
type = "cron"
cron = "0 22 * * 1-5"
start_date = "2025-08-04T00:00:00Z"
catchup = "sequential"
```

This schedule fires at 22:00 UTC every weekday. On first registration, the
scheduler creates one logical run for every missed weekday since August 4,
2025. `sequential` runs those intervals in order before moving to the next one.

Use a different catch-up policy only when the worker and upstream source can
support it:

| Policy | Behavior |
| --- | --- |
| `sequential` | Run missed intervals one at a time, oldest first. |
| `parallel` | Make all missed intervals eligible together. |
| `none` | Skip history and start with the next live interval. |

The scheduler stores cron state and jobs in Postgres. Restarting or replacing
the scheduler does not lose the backfill position or enqueue duplicate logical
   WHERE symbol = '\''SPY'\'''
```

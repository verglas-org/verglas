---
title: "Rill dashboards"
description: "Run a Rill Explore dashboard against the live Verglas query engine."
---

The Analytics profile runs Rill with the Verglas OLAP connector. Rill owns the
project, metrics views, and dashboards. Each dashboard request sends SQL to
`POST /v1/query`; Verglas resolves the current Iceberg table state and returns
an Arrow stream. There is no copied model, pinned metadata snapshot, or refresh
command.

## Start the analytics service

The repository includes a Rill project under `deploy/rill`. Start it with the
rest of the self-hosted application:

```bash
docker compose --profile analytics up --detach --build
```

Open [http://127.0.0.1:9009](http://127.0.0.1:9009). The supplied
`market_ohlcv` Explore uses the live `market.ohlcv` table.

## Define dashboards in Rill

Rill resources are ordinary project files. The connector is
`deploy/rill/connectors/verglas.yaml`:

```yaml
type: connector
driver: verglas
endpoint: http://verglas-server:8334
```

Metrics views and Explore dashboards live under `deploy/rill/metrics` and
`deploy/rill/dashboards`. Add or edit them with Rill's normal project workflow;
Verglas does not create, list, show, delete, or persist dashboard resources.

## Query behavior

The connector implements Rill's live `OLAPStore` interface. It discovers
tables and columns through Verglas `information_schema`, sends parameterized
DuckDB-dialect SQL to the query API, and decodes Arrow IPC results directly.
Every query creates a new Verglas execution against the catalog's current
Iceberg snapshot, so a committed backtest is visible without rebuilding a Rill
model.

Verglas remains the cache and execution layer. The catalog and customer bucket
remain authoritative, and stopping Verglas only requires pointing another
query engine at those same tables.

RIME is an evolutionary algorithm over code states. It descends from AIDE's
tree search and keeps AIDE's loop, but its structure is the classic
evolutionary one: a population of candidates, mutation operators, a fixed
fitness function, and selection pressure applied generation by generation.
The normative operator contract lives in the RIME package
(`rime/skills/rime/references/algorithm.md`); this page explains the design.

## The evolutionary mapping

| Evolutionary term | RIME construct |
|---|---|
| Genome | One code state: a git tree, identified by its commit SHA |
| Individual | A candidate — one mutated state plus its compact selection properties |
| Mutation operators | `draft` (new individual from the baseline), `debug` (repair a buggy individual), `improve` (one atomic change to a lineage's best individual) |
| Fitness function | The frozen evaluator: hard gates, measured metrics, and a deterministic scalar utility |
| Generation | A wave — one policy decision fanned out into parallel attempts, invisible to selection until its closed state is recorded |
| Selection | Lineage-bandit UCB over draft arms; the arm's best valid candidate is the improvement parent |
| Survival | Promotion — one winner replaces the trunk; losing workspaces are removed |
| Heredity across runs | Caller-managed state and evidence supplied through RIME's injected boundaries |

Two properties separate RIME from an unconstrained genetic search. First, the
fitness function is frozen before any mutation, so candidates never optimize
against a moving target and a worker's claim of fitness is never accepted —
the coordinator re-evaluates independently. Second, every `improve` mutation
must be one atomic change, so the effect of each mutation stays measurable in
its fitness delta.

## Code-state identity

Git SHAs identify the code state that each candidate evaluates. The contract is:

- **Every candidate records its parentage as SHAs.** An attempt starts from a
  parent state (`parentSha`: the commit its workspace branched from, plus the
  baseline it restored) and produces a result state. Speculative workspace
  states are identified by their workspace branch head; promoted states by the
  trunk commit they became.
- **Promotion advances the trunk.** The selected candidate becomes the next
  state when its work is promoted. The caller may retain the resulting commit
  and its evaluator summary for later runs.
- **Evidence pins to the state it measured.** Evaluator artifacts carry the SHA
  or other state identity they describe. Results from different workspaces are
  sibling candidates in the same wave and are resolved by selection.

## Where it runs

The coordinator owns policy, evaluation, wave closure, promotion, and cleanup.
Mutation workers own exactly one candidate each, in isolated workspaces, and
report evidence rather than judgments. Host integrations (Claude Code, Codex,
Cursor, Pi) supply worker execution and workspace isolation; the search core
assumes none of them. RIME returns the candidate state and evaluator evidence
through its injected boundaries.

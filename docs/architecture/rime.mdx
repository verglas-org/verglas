RIME is an evolutionary algorithm over code states. It descends from AIDE's
tree search and keeps AIDE's loop, but its structure is the classic
evolutionary one: a population of candidates, mutation operators, a fixed
fitness function, and selection pressure applied generation by generation.
This page names that structure and specifies the evolution record. The
normative operator contract lives in the RIME package
(`rime/skills/rime/references/algorithm.md`); this page explains the design.

## The evolutionary mapping

| Evolutionary term | RIME construct |
|---|---|
| Genome | One code state: a git tree, identified by its commit SHA |
| Individual | A candidate — one mutated state plus its compact selection properties |
| Mutation operators | `draft` (new individual from the baseline), `debug` (repair a buggy individual), `improve` (one atomic change to a lineage's best individual) |
| Fitness function | The frozen evaluator: hard gates, measured metrics, and a deterministic scalar utility |
| Generation | A wave — one policy decision fanned out into parallel attempts, invisible to selection until its `WaveClosed` fence lands |
| Selection | Lineage-bandit UCB over draft arms; the arm's best valid candidate is the improvement parent |
| Survival | Promotion — one winner replaces the trunk; losing workspaces are removed |
| Heredity across runs | Precedent search over `Decision` nodes (#148): past selections inform new gates and wave sizing |

Two properties separate RIME from an unconstrained genetic search. First, the
fitness function is frozen before any mutation, so candidates never optimize
against a moving target and a worker's claim of fitness is never accepted —
the coordinator re-evaluates independently. Second, every `improve` mutation
must be one atomic change, so the effect of each mutation stays measurable in
its fitness delta.

## The evolution record: git SHAs as state identity

The project graph is the genealogy of the search, and git SHAs are its state
identity. The contract:

- **Every candidate records its parentage as SHAs.** An attempt starts from a
  parent state (`parentSha`: the commit its worktree branched from, plus the
  baseline it restored) and produces a result state. Speculative worktree
  states are identified by their worktree branch head; promoted states by the
  trunk commit they became.
- **Promotion advances the trunk.** A `Decision` node records the selection
  act; when the promoted work lands as a commit, the decision's `resultSha`
  names it. The chain of decisions is the trunk's evolution history, and
  `graph precedents` searches it.
- **Evidence pins to the state it measured.** A claim's provenance carries the
  SHA (or Iceberg snapshot id) it was true at. Two claims at different SHAs
  are succession, not contradiction: the newer state supersedes the older via
  the edge model's `supersedes` pointer. Claims from different worktrees are
  sibling divergence — the normal state of a generation, resolved by
  selection, never treated as conflict.
- **The lakehouse supplies the time axes.** Iceberg snapshots give transaction
  time (when a fact was recorded); the SHA in provenance gives valid time
  (which state the fact describes). Together the graph is a bitemporal
  evolution record without dedicated bitemporal machinery: `--at` time travel
  replays the record as of any commit of the search itself.

The result is that "how did this code evolve" is a graph query: walk decisions
trunk-ward for the promotion history, walk a candidate's lineage for its
mutation path, and walk `evidenced_by` edges at a pinned SHA for what was
known when a selection was made.

## Where it runs

The coordinator owns policy, evaluation, wave closure, promotion, and
cleanup. Mutation workers own exactly one candidate each, in isolated
workspaces, and report evidence rather than judgments. Host integrations
(Claude Code, Codex, Cursor, Pi) supply worker execution and worktree
isolation; the search core assumes none of them. Runs persist through
`VerglasGraphStore` into the project graph `rime_<project>`, and a create-once
json-render dashboard replays the population live as waves close.

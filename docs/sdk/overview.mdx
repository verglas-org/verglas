The Verglas SDKs expose the same endpoint contract against a local self-hosted server. A worker receives a connected client. A standalone application or a Vessel connects with an endpoint and bearer token scoped to the data it needs.

<Warning>
The SDK packages are private workspace packages in the current prototype. Install them from this repository until published packages become available.
</Warning>

| Connect to a local endpoint | `connect` | `Client::connect` |
| Create or verify a table definition | `ensureTable` (Iceberg REST) | `ensure_table` (Iceberg REST) |

| Integration namespaces | `client.namespace` | `Client::namespace` |

| Queue operations | `queue.enqueue`, `poll`, `ack` | `Client::queue` → `enqueue`, `poll`, `ack` |
| Property graphs | `graph.create`, insert, index, traverse | `Database::graph` → create, insert, index, traverse |
| Vector indexes | `addIndex`, `listIndexes`, `searchIndex` | `Database::table` → `add_index`, `list_indexes`, `search_index` |
| Worker authoring | `defineWorker`, `runWorker` | `Worker` trait and `WorkerContext` |

Catalog commit following is not on the live on-prem router. Poll the selected database's Iceberg metadata or query results when an application needs change detection.

## Endpoint model

The SDK separates three destinations:

- The **Verglas endpoint** handles query and logical write execution.
- The **Iceberg REST catalog** handles table metadata and table creation.
- The **S3-compatible cache endpoint** handles object bytes.

Local clients can discover the catalog and S3 endpoint from the server admin API.

## Authentication

Do not hard-code a token. Workers receive a connected client and secret bindings through their context. Standalone applications read `VERGLAS_ENDPOINT` and `VERGLAS_TOKEN` from their environment.

```bash
export VERGLAS_ENDPOINT=http://127.0.0.1:8334
export VERGLAS_TOKEN=replace-with-a-scoped-token
```

A worker runtime receives a scoped data-plane token for its table grants.

Follow [Get your first result](/docs/get-started/first-table) before adapting a
client to `analytics` and `market.ohlcv`. The SDK does not create a second data
format: reads and writes remain ordinary Iceberg operations through the
configured catalog and S3 cache path.

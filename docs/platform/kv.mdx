---
title: "KV"
description: "Store small tenant-scoped values in Verglas with durable local writes and TTLs."
---

Verglas includes a persistent key-value engine. It is always available when the
server is running. There is no KV feature flag or `[kv]` configuration section.

Each key belongs to an authenticated tenant and an application-chosen namespace.
Values are raw bytes up to 8 MiB. A recently read or written value is served from
RAM; colder values are read from the same durable NVMe volume as the server's
cache. KV records live in `cache.dir/kv` and are independent from cached S3
objects, so object-cache eviction and purge operations do not remove them.
KV and acknowledged write-back bytes are non-evictable. They consume the shared
disk budget by their actual size; there is no KV partition or reserved fraction.
All remaining object-cache space continues to admit and evict data by heat.

## Set and get a value

<CodeGroup>

```typescript TypeScript
const kv = client.kv("workshop.blueprints");

await kv.put("featured", new TextEncoder().encode("blue"), {
  ttlSeconds: 300,
  contentType: "text/plain",
});

const value = await kv.get("featured");
if (value) console.log(new TextDecoder().decode(value.bytes));
```

```rust Rust
use bytes::Bytes;
use verglas_sdk::KvPutOptions;

let kv = client.kv("workshop.blueprints")?;
kv.put(
    "featured",
    Bytes::from_static(b"blue"),
    KvPutOptions {
        ttl_seconds: Some(300),
        content_type: Some("text/plain".to_owned()),
        ..KvPutOptions::default()
    },
).await?;

if let Some(value) = kv.get("featured").await? {
    println!("{}", String::from_utf8_lossy(&value.bytes));
}
```

</CodeGroup>

`put` returns an opaque version. Pass that version as `ifMatch` / `if_match` to
make the next put or delete conditional. Use `createOnly` / `create_only` to
create a key only when no live value exists, and an idempotency key to retry a
write without creating a second logical version.

Expired values are immediately unreadable and absent from listings. Physical
space may be reclaimed later. `list` returns metadata only, in deterministic
bytewise key order, with a bounded page size and an opaque continuation cursor.

## Durability and lifecycle

A successful put or delete has been synchronized to the local KV log. Verglas
recovers values, versions, expirations, and tombstones after graceful shutdown or
process termination. When the bounded local capacity cannot accept a record,
the write fails explicitly; live values are never silently evicted.

KV data is local deployment state. It is not copied to the customer's object
store, replicated to another Verglas node, or protected by erasure coding.
Destroying or replacing the mounted Verglas data volume destroys the KV data.
For Docker deployments, keep the existing `/var/lib/verglas` volume mounted to
preserve both the object cache and KV engine across container replacement.

## When to use KV

Use Verglas KV for small, latency-sensitive coordination state such as cursors,
watermarks, leases, deduplication markers, and compact application settings.

- Use Postgres for relational queries, transactions spanning many records, or
  data that must survive loss of one Verglas node.
- Use Iceberg for analytical datasets, historical records, and snapshot-based
  table operations.
- Use S3 for large immutable objects and customer-owned durable files.

KV is tenant and namespace scoped. Self-hosted access uses the server's existing
credentials; hosted deployments can issue read-only or read-write namespace
tokens. Keys, values, bearer tokens, and application metadata are never written
to request logs.

---
title: "S3 listener semantic APIs"
description: "S3 Vectors, Graph, Iceberg catalog, and Swagger endpoint topology."
---

These are independent cache-node infrastructure APIs, not additional products
in the six-product platform. The cache node S3 listener owns ordinary S3
requests and the direct semantic REST-JSON APIs. It authenticates both semantic
services with AWS SigV4, never with a bearer token: use signing name `s3vectors`
for S3 Vectors and `verglasgraphs` for Graph. Durable Objects do not own these
mutation domains; explicit graph/vector operations remain responsible for any
index publication.

The S3 Vectors service uses the exact modeled operations /CreateVectorBucket,
/CreateIndex, /PutVectors, and /QueryVectors. The Graph service uses
/CreateGraph, /ListGraphs, /DescribeGraph, /DeleteGraph, /AddNodes, /AddEdges,
/RetrieveNeighbors, /SearchKHop, /SearchNeighborhood, /SearchPaths,
/SearchPrecedents, and /BuildIndex. The full checked-in listener contract
is served at /api-docs/s3/openapi.json; /swagger-ui links to that document.

Rust callers construct S3VectorsClient or VerglasGraphsClient with cache
listener credentials. TypeScript callers use the identically named clients.
Both clients sign each direct model path and do not use retired /v1 vector,
graph, query, or write routes.

Iceberg engines use a separate catalog endpoint together with the cache-node
S3 endpoint. Verglas Cloud exposes its managed Lakekeeper REST catalog and its
catalog Swagger from the cloud service. A self-hosted cache may point at that
service or at another Iceberg catalog; the open-source cache listener does not
host `/catalog/v1`.

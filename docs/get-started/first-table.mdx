This guide continues from [Self-host Verglas](/docs/get-started/self-host).
You will create the managed `analytics` lakehouse, put two daily bars in
`market.ohlcv`, and run a query twice. That table is the running example for
the worker, Vessel, dashboard, and SDK guides.

## Before you begin

Confirm that the stack is ready, then point the CLI at it. Use the scoped token
created during self-hosting; the database operations need the matching grants.

```bash
export VERGLAS_ENDPOINT=http://127.0.0.1:8334
export VERGLAS_ACCESS_ENDPOINT=http://127.0.0.1:8345
export VERGLAS_TOKEN=TOKEN_SHOWN_ONCE
verglas status
```

## Create the database

```bash
verglas db create analytics --type lakehouse
```

Verglas creates an `analytics` warehouse in the tenant Lakekeeper catalog.
The deployment R2 bucket remains the durable store; this is a logical
lakehouse, not a new object-store credential or a private copy of your data.

## Create the table

Create `market-bars.jsonl`. The first write establishes the Iceberg schema.

```json market-bars.jsonl
{"symbol":"SPY","timestamp":"2026-08-03T20:00:00Z","open":631.20,"high":633.91,"low":629.88,"close":632.08,"volume":71345000}
```

```bash
verglas table create market.ohlcv ./market-bars.jsonl
```

Expected result: the CLI reports `market.ohlcv` and one committed row. Verglas
writes ordinary Iceberg metadata and Parquet to R2, then commits the metadata
location through Lakekeeper.

## Add one more day

```json more-market-bars.jsonl
{"symbol":"SPY","timestamp":"2026-08-04T20:00:00Z","open":632.44,"high":635.12,"low":630.77,"close":634.89,"volume":68112000}
```

```bash
verglas table append market.ohlcv ./more-market-bars.jsonl
```

## Query, then repeat

The isolated query role reads the catalog metadata and Parquet bytes through
the Verglas S3 cache endpoint.

```bash
verglas query analytics \
  'SELECT symbol, timestamp, close, volume
   FROM market.ohlcv
   ORDER BY timestamp'
```

Expected result: two SPY rows, ordered from August 3 to August 4. Run the same
query again, then inspect activity:

```bash
verglas table metrics
```

The repeated query is the cache observation, not a benchmark. A small table or
a cold/restarted cache may still show passthrough reads or no visible hit; the
result bytes must be the same either way. Cache hits require catalog-backed
Parquet reads, and the cache never replaces the catalog or R2 as authority.

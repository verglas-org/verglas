# verglas-do-engine worklog

Append-only log of changes to this crate, by issue. Every PR touching this crate adds an entry.

- #171: Added the first DataFusion-backed Durable Object transaction slice. It defines deterministic Arrow envelopes, explicit snapshot scans, private SQL write sets, one commit-authority seam, atomic cross-domain watermarks, INSERT DML, read-your-writes sessions, preflight validation, and tests proving ACK-gated visibility and exact retry encoding.
- #171: Added ordered asynchronous transaction archive with retry-safe watermarks and a provider-neutral object-store sink that uploads and reads back canonical envelopes before advancing. Defined the open-source SQL DO, Lakehouse DO, and non-durable query-object policies so cloud composition cannot accidentally give a cache-only query object a Raft group or transaction offload stream.
- #171: Added the per-replica SQLite pager with WAL/FULL durability, contiguous committed transaction application, exact-retry detection, persisted archive/checkpoint watermarks, and restart replay into live Arrow MVCC state. Canonical envelopes now decode deterministically for follower apply and process recovery, and persistent engines write SQLite after authority commit but before exposing local visibility.
- #171: Connected the engine commit seam to the real Verglas consensus group through `RaftCommitAuthority`. It submits the exact canonical envelope as a coded `DoTransaction`, uses the consensus-owned logical DO sequence rather than a raw Raft index, maps conflicts closed, and exposes a narrow submitter seam with a test proving UUID, holder set, bytes, and receipt mapping.
- #171: Added a live Vamana projection for vector-domain mutation batches. Registration rebuilds from the canonical committed log, each acknowledged vector batch updates exact rows and the Vamana delta at the same transaction sequence, queries exact-rerank all live rows, and restart tests prove SQLite replay reconstructs the index without a second authority.
- #171: Added live forward and reverse graph adjacency over standard Arrow edge batches. Graph commits apply append-only assertions and supersession tombstones at the transaction sequence, expose predicate-filtered neighbor lookup, and rebuild deterministic CSR adjacency from SQLite replay after restart.
- #171: Added asynchronous Vamana and graph Puffin artifact generation with explicit nonempty transaction coverage. A provider-neutral object-store publisher writes deterministic immutable paths, reads bytes back, verifies identity with SHA-256, and returns coverage receipts; publication remains explicitly invoked rather than autonomously targeting customer storage.
- #171: Added the runnable supervised `verglas-do` child and its private Unix endpoint. Each process opens its exclusive SQLite WAL/FULL pager, reports durable watermarks, applies canonical committed envelopes with identity and sequence checks, serves only covered follower snapshots, and rejects stateful Worker dispatch unless launched as leader; an end-to-end process test verifies the host argument contract, socket bind, and pager creation.
- #171: Replaced the abandoned per-DO Raft authority with the clarified isolated-worker durability contract and renamed the child binary `verglasd`. Default commits create and verify immutable canonical transaction objects before a lease-generation-fenced S3 head CAS; optional early acknowledgement fans exact bytes to five Unix replica endpoints and requires three durable SQLite replies, whose persisted lease fence rejects stale workers.
- #171: Added atomic launcher handoff for an already-held managed S3 lease. A higher generation conditionally replaces the head while preserving its transaction identity and sequence, immediately fencing the old worker; public grants carry the exact ETag/version needed to start a worker without reacquisition.
- #171: Added real SQLite recovery checkpoints for scale-to-zero. Publication uses `VACUUM INTO`, uploads an immutable sequence-and-hash path, reads bytes back before advancing the local checkpoint watermark, and restore verifies SHA-256 before an fsynced temporary-file rename and DO identity check.
- #171: Added an executable non-durable query object that acquires one opaque dataset cache pin, runs registered read providers through DataFusion, and releases the reservation on drop without exposing a transaction authority. Removed the stale Raft terminology from object policy and replaced it with the configured durable-authority contract.
- #171: Added the Lakehouse publication primitive with managed-versus-customer binding enforcement. Managed bindings may publish covered artifacts autonomously, customer bindings require explicit invocation, and deterministic artifact paths now use create-only writes so exact retries succeed while conflicting bytes fail closed.
- #171: Renamed local endpoint roles from leader/follower to worker/replica. Every stateful DO worker may execute events, while optional replica endpoints only persist lease-fenced transactions and serve covered snapshots.
- #171: Replaced the client-side five-endpoint quorum with one configured replica service, whose deployment may provide its own regional durability. The lease-fenced Unix protocol now supports durable apply, bounded failover replay, and explicit clean-through-watermark; stale workers cannot clean data, and replay below a cleaned watermark fails closed.
- #171: Added authority-backed `COMMIT` to the private worker endpoint and wired replica durability into the real `verglasd` process. A worker now starts with its held lease and sequence, replays the replica tail into a fresh SQLite pager before binding, commits exact canonical envelopes through the replica service, and refuses a mismatched recovered sequence; a real-process test kills the worker, starts a replacement directory, and proves replay restores its applied state. Exact client retries return the persisted receipt without resubmitting to the authority, while conflicting bytes fail closed.
- #171: Moved the `verglasd` executable target and its process acceptance test into `verglas-runtime`, which owns runtime composition. The engine crate remains the reusable DataFusion, authority, SQLite, and endpoint implementation without an executable packaging dependency.
- #171: Added a deterministic shared offload batcher with production thresholds of ten seconds and sixteen MiB plus explicit drain. It rejects cross-DO or noncontiguous ranges so compacted SQLite archive and Iceberg publication can consume the same exact transaction coverage.
- #171: Bound worker `COMMIT` to the persistent `DoEngine` rather than applying only to the SQLite pager. Added private `REGISTER` and `QUERY` operations so each real worker owns a DataFusion session over its authoritative transaction projections, and replay reconstructs those queryable projections after failover.
- #171: Added a create-only compacted transaction archive with deterministic contiguous range paths and read-back verification. `DoEngine::drain_offload` now applies the shared ten-second/sixteen-MiB policy, publishes compacted ranges, and advances SQLite and in-memory archive watermarks only after a valid verified receipt.
- #171: Wired managed offload into worker endpoints: archive-enabled workers autonomously drain every ten seconds, flush immediately at sixteen MiB, and expose explicit `DRAIN`. Removed the obsolete unfenced `APPLY` command and role-fenced replica apply, replay, and clean operations so worker and replica protocol surfaces cannot be crossed.
- #171: Gated replica `CLEAN` on both persisted verified archive and checkpoint watermarks before deleting committed transaction rows. Added direct pager and Unix-endpoint regressions proving uncovered state remains replayable and covered state can still be cleaned.
- #171: Made legacy per-transaction archive objects create-only as well as compacted ranges. Exact retries read back and verify identical bytes; a conflicting preexisting deterministic path now fails without overwriting durable data.
- #171: Added held lease ETag/version accessors and managed-CAS worker recovery support. CAS workers validate the launcher grant against the managed head, restore the newest verified SQLite checkpoint, replay a contiguous immutable transaction tail, and expose explicit checkpoint publication with CAS archive watermarks.
- #171: Added failing-first acceptance coverage for serializable conflicts, DataFusion UPDATE/DELETE, explicit snapshot fences, durable empty schemas, and canonical upserts. The tests define the transaction semantics required before implementation lands.
- #171: Added serializable snapshot validation, canonical Replace/Upsert mutations, transactional DataFusion UPDATE/DELETE plans, explicit session fences, and replayable schema declarations for empty tables. Commits write verified Parquet manifests, record commit-range and index coverage summaries, use a catalog CAS with retry identity, preserve managed-versus-customer authorization, and advance archive watermarks only after standard Iceberg metadata and scan verification.

# verglas-celld worklog

Append-only log of changes to this crate, by issue.

- #171: Added the tenant-cell placement foundation for three supervised single-group DO replicas. Placement enforces hard follower and leader resource reservations, prefers the active Worker host only when it has leadership headroom, and otherwise balances by CPU, memory, current leaders, and recent transaction load with deterministic tests.
- #171: Added the supervised child lifecycle safety state machine. Durable children refuse suspension until both transaction archive and checkpoint cover applied state, restored children remain unroutable below the triggering fence, followers may serve only covered snapshots, and only leaders execute stateful Worker events.
- #171: Added the concrete host-local process supervisor. It validates isolated DO identities, creates per-replica data and Unix-socket paths, launches real child processes with host/role arguments, fences stateful and snapshot routing through lifecycle state, kills only after archive/checkpoint gates, and starts restore processes without routing them before recovery finishes. The supervisor does not expose a route until the child has bound a real Unix socket. Host polling reaps unexpected exits and immediately moves the replica behind its applied recovery fence.
- #171: Added the runnable `celld-host` binary and its bounded newline-delimited Unix control protocol. Placement agents can spawn, suspend, restore, finish recovery, and resolve fenced routes through one root-local socket; malformed commands fail without mutating supervision, and daemon shutdown terminates remaining children. Restore now launches the child in the elected target role and rejects a mismatched recovery completion, preventing supervisor and endpoint leadership from diverging.
- #171: Updated the supervised worker naming to `verglasd` after the deployment contract was clarified as one Worker and SQLite engine per isolated microVM. The existing process supervisor remains the lifecycle boundary while microVM provisioning and hard runtime enforcement are connected.
- #171: Updated the child launch wire values to `worker` and `replica`, matching the non-Raft runtime contract. The worker executes stateful events; optional replicas remain durability and fenced-snapshot endpoints only.
- #171: Added per-DO held durability to child specifications and the `SPAWN_WORKER` control command. `celld-host` now passes each worker's replica socket, opaque lease token, generation, and exact recovered start sequence to `verglasd`; invalid role, empty token, or a sequence that disagrees with the lifecycle fence is rejected before process launch.
- #171: Moved the `celld-host` executable target into `verglas-runtime` beside `verglasd` so Cargo can build and expose both binaries to one real-process acceptance test. This crate remains the reusable supervision, lifecycle, placement, and control implementation.
- #171: Extended `SPAWN_WORKER` with an explicit managed-offload directory or `-` for disabled offload. The supervisor passes `--offload-dir` only to enabled workers, allowing catalog DOs to use ordinary worker durability while prohibiting recursive Lakehouse publication.
- #171: Added a strict `PID <do-id>` control query for acceptance diagnostics and process-isolation assertions. It returns only a currently supervised child process and fails for suspended or unknown DOs.
- #0: Extracted the compute substrate behind the `Provisioner` seam, retaining local process behavior as the default and adding a fail-closed Fly Machines configuration skeleton. The supervisor now routes readiness, kill, wait, and reap operations through the seam while preserving archive/checkpoint and restore fencing, covered by a recording-provisioner lifecycle test.
- #0: Added the substrate-neutral `AlarmSchedule` with one replaceable derived deadline per DO, deterministic Tokio-time tests, and supervisor arm/disarm integration. Wake delivery remains advisory: handlers must re-read committed alarm state, and restore re-arming remains at the routing-layer fence extension point.
- #0: Extended local child readiness to a 180-second cold-start budget because component instantiation can take minutes before `verglasd` binds its control socket. Added a regression test proving a delayed child is still published only after it binds.
- #0: Let one logical DO supervise a follower durability endpoint and a Worker endpoint at once. The follower gets a host-local pager key but still launches `verglasd` with the logical DO identity, so replica envelope validation and Worker routing agree without sharing filesystem paths.
